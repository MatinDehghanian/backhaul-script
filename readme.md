# Backhaul Script

Interactive Bash installer and tunnel manager for Backhaul. Configure IRAN (server) and KHAREJ (client) tunnels, manage systemd services, view logs, and update the Backhaul executable.

## Requirements

- A Linux server with systemd and root access.
- Bash 4 or newer, curl, and jq. The script installs jq with apt-get if it is missing; this requires sudo to be available.
- OpenSSL for generating TLS certificates when needed.
- Access to raw.githubusercontent.com to download the script and executable.

The bundled `backhaul` executable targets Linux x86-64. Use a compatible server.

## Install and run

Run this command in a root Bash shell on each server:

```bash
bash <(curl -Ls --ipv4 https://raw.githubusercontent.com/MatinDehghanian/backhaul-script/refs/heads/main/backhaul.sh)
```

If you are logged in as a non-root user, enter a root shell first:

```bash
sudo -i
```

To save the script locally and run it:

```bash
curl -fLsS --ipv4 https://raw.githubusercontent.com/MatinDehghanian/backhaul-script/refs/heads/main/backhaul.sh -o backhaul.sh
chmod +x backhaul.sh
sudo ./backhaul.sh
```

On first run, the script downloads the executable directly from:

```text
https://raw.githubusercontent.com/MatinDehghanian/backhaul-script/refs/heads/main/backhaul
```

It applies `chmod +x` and installs the executable at `/root/backhaul-core/backhaul_premium`, the path used by its systemd services.

## Configure a tunnel

1. On the IRAN server, choose **1. Configure a new tunnel**, then **1) Configure IRAN (Server)**.
2. Follow the prompts for the bind address, transport, security settings, and port mappings.
3. On the KHAREJ server, run the same script and choose **1. Configure a new tunnel**, then **2) Configure KHAREJ (Client)**.
4. Enter the IRAN server address and port. Use matching transport and security settings on both sides.
5. Choose **3. Check tunnel status** to inspect the services.

The script offers these transports: `tcp`, `tcpmux`, `xtcpmux`, `ws`, `wss`, `wsmux`, `wssmux`, `xwsmux`, `anytls`, and `tun`.

## Manage and update

| Menu option | Action |
| --- | --- |
| 1. Configure a new tunnel | Create a server or client tunnel and its systemd service. |
| 2. Tunnel management | Edit, test connectivity, export setup links, check health, start/stop, restore the previous config, inspect logs, or delete a tunnel. |
| 3. Check tunnel status | Check configured tunnel services. |
| 4. Update Backhaul Core | Download the latest executable from this repository. Restart existing tunnel services afterward through tunnel management. |
| 5. Update script | Download the latest script from this repository's GitHub raw URL, validate it, and install it as executable `/usr/bin/backhaul`. Run `backhaul` to reopen it. Failed updates keep the installed script. |
| 6. Remove Backhaul Core | Remove the core after deleting all tunnel services. |
| 0. Exit | Close the menu. |

## File locations

- Core and tunnel configurations: `/root/backhaul-core/`
- Server configurations: `/root/backhaul-core/iran<port>.toml`
- Client configurations: `/root/backhaul-core/kharej<port>.toml`
- TLS certificate files: `/root/backhaul-core/cert_files/`
- systemd services: `/etc/systemd/system/backhaul-iran<port>.service` and `/etc/systemd/system/backhaul-kharej<port>.service`

Rerun the install command whenever you want to open the menu again.

## Edit an existing tunnel

1. Choose **2. Tunnel management** and select your tunnel.
2. Choose **5) Edit this tunnel (easy menu)**.
3. Select a settings group, then the numbered setting to change. Current values are displayed; press Enter to keep a value. Boolean settings and choices such as transport use numbered options.
4. To change transport, open **Transport and connection options** and select **Type**. The editor keeps shared settings and asks for missing transport details, including mux, TLS, TUN, and IPX settings. TUN forwarding supports individual ports and `port=port` mappings; incompatible ranges will prompt for replacement.
5. Choose **s) Save changes and restart tunnel** to apply your edits. Choose **0) Cancel** to discard them.

Saving creates a `.toml.bak` backup and restarts the existing tunnel service. If the restart fails or the service is inactive, the script restores the previous configuration and attempts to restart it. Service and configuration filenames stay the same, even if you edit a connection port.

When changing transport or security settings, update the other server to match. The menu edits the selected server's configuration only.

The editor supports the TOML format generated by this script. It preserves additional compatible scalar fields and sections, but refuses unsupported TOML syntax without changing the file. Saving removes comments and normalizes formatting.

## Setup KHAREJ from a link

1. Configure IRAN first. After creation, the script asks for the IRAN IP/domain that KHAREJ can reach and prints a `backhaul://1.…` setup link. You can also generate it later from **Tunnel management → select an IRAN tunnel → 7) Show setup link for KHAREJ**.
2. On KHAREJ, choose **Configure a new tunnel → 3) Setup KHAREJ from an IRAN setup link** and paste it.
3. The script fills in the matching transport, credentials, mux settings, tuning and connection details. For TUN it swaps the local/remote addresses; for IPX it swaps the peer IPs and asks for the local network interface.
4. Review the preview, then enter `y` to create and start the tunnel.

After editing IRAN, export a fresh link and apply it on KHAREJ. If exactly one existing KHAREJ tunnel has the same credential, it updates that tunnel with a backup and restart instead of creating another instance. Conflicting filenames and TUN devices are refused.

Links contain credentials and are encoded, not encrypted. Share them privately. These are this script's links; BackPack's `backpack://` format is not compatible. New manual setups generate a random token or IPX PSK instead of a shared fixed default.

## Test one tunnel's connection

Choose **Tunnel management → select a tunnel → 6) Test connection**. Diagnostics require Python 3; on Debian/Ubuntu, install it with `apt-get install -y python3` if needed.

Choose one test:

- **1) Quick TCP reachability:** ten sequential TCP connects to the selected tunnel address. On KHAREJ this measures the route to IRAN; on IRAN it checks the local listener only. It reports connection success, connect latency and jitter. These results do not prove authentication or forwarded traffic, and failed connects are not a measurement of packet loss. IPX does not use this TCP listener check.
- **2) Real traffic test (IRAN):** select one configured port mapping. The script prints a `backhaul-test://1.…` link. On KHAREJ, select the matching tunnel, choose **3) Start responder**, and paste that test link. Once KHAREJ says **Ready**, press Enter on IRAN. The test verifies 60 echoes over one persistent connection, then an exact 1 MiB bulk echo. It reports round-trip latency, jitter and the combined upload/download echo rate.

The KHAREJ backend port must be unused: the responder refuses occupied ports and never stops an application. If necessary, add an unused mapping such as `55000=55000` through **Edit → Port mappings**, then remove it after testing. Range mappings let you choose one port in the range.

Only the selected existing tunnel carries test traffic. Testing starts no additional Backhaul core, changes no tunnel configuration, and does not try other transports or other mappings. A lock allows one diagnostic test per server at a time. To compare transports, edit both ends (or update KHAREJ using a fresh setup link), then test the new transport separately.

Keep the test link private. The temporary responder supports PROXY protocol headers and exits when the test finishes, when you cancel with Ctrl+C, or after ten minutes. A successful echo test proves the selected path carried those test bytes; it does not test every forwarded service or guarantee future route quality.

## Health and recovery

The selected tunnel's management menu also offers:

- **8) Health check and file locations:** core executable permissions, service state, weak default-token detection, TLS expiry, config/backup/service paths and the selected service's recent logs. It reports suggestions without changing settings.
- **9) Start / stop this tunnel:** controls only that service. Stopping does not disable its existing boot setting.
- **10) Restore previous configuration:** previews the transport in the `.toml.bak` file, then restores and restarts only the selected tunnel after confirmation. If the restored configuration cannot start, it recovers the current configuration.

The [BackPack feature review](docs/backpack-review.md) records the source reviewed, the features adapted, and which features require a different tunnel engine.

## Verify editor changes

Tests use temporary files and simulated systemd services. With Bash 4+, jq, and Python 3.11+ installed:

```bash
bash tests/tunnel_edit_test.sh
bash tests/tunnel_features_test.sh
python3 tests/connection_tool_test.py
```

The last test uses loopback sockets and takes about one minute to verify the full echo soak. Tests simulate systemd; they do not run the Linux Backhaul binary or contact your servers. Use `TEST_BASH=/path/to/bash` for the Python test if your default Bash is older than version 4.
